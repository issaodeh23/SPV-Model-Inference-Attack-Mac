## 1. Overview

This report documents our replication of the SPV-MIA membership inference attack from the NeurIPS 2024 paper:

> *"SPV-MIA: Membership Inference Attacks with Self-Prompted Variation on Large Language Models"*

A **Membership Inference Attack (MIA)** asks: given a text sample and a trained language model, can we determine whether that text was part of the model's training data? This has direct implications for privacy — if an attacker can identify training data membership, they can infer that individuals' private data was used to train a model.

SPV-MIA's key contribution is a self-calibrated, perturbation-based approach that works even on generalized (non-overfit) models. The attack:
1. Generates slightly perturbed versions of each text using T5
2. Measures how sensitively the target model reacts to those perturbations
3. Calibrates the signal using a reference model trained on text generated by the target model itself

## 4. Procedure

The full pipeline runs in five sequential steps via `_run_pipeline.sh`:

**Step 1 — Fine-tune Target Model**  
GPT-2 is fully fine-tuned on 50,000 packed sequences from Wikitext-103. This is the model that the attack will later attempt to extract membership information from.

| Hyperparameter | Value |
|---|---|
| Fine-tuning method | Full fine-tuning |
| Epochs | 10 |
| Batch size | 16 |
| Learning rate | 1e-4 |
| Optimizer | AdamW |
| Training samples | 50,000 |
| Saved checkpoint | `ft_llms/gpt2/wikitext-103-raw-v1/target/checkpoint-31250` |

**Step 2 — Generate Self-Prompt Reference Data**  
The fine-tuned target model generates 10,000 new text samples by completing short prompts drawn from a held-out slice of the dataset (samples 10,000–20,000). This data is used to train the reference model.

**Step 3 — Fine-tune Reference Model**  
A second GPT-2 model is fine-tuned on the self-prompted data. Its role is to capture the target model's general language tendencies without having seen the actual training data.

| Hyperparameter | Value |
|---|---|
| Fine-tuning method | LoRA |
| Epochs | 4 |
| Batch size | 16 |
| Learning rate | 5e-5 |
| Training samples | 50,000 |
| Saved checkpoint | `ft_llms/gpt2/wikitext-103-raw-v1/refer/checkpoint-2500` |

**Step 4 — Run SPV-MIA Attack**  
The attack evaluates 1,000 member texts (seen during training) and 1,000 non-member texts (unseen). For each text, it generates 10 perturbed versions using T5-base, scores each through both the target and reference models, and computes a calibrated variation score.

| Attack Parameter | Value |
|---|---|
| Members evaluated | 1,000 |
| Non-members evaluated | 1,000 |
| Perturbations per sample | 10 |
| Span length masked | 2 tokens |
| Mask percentage | 30% |
| Mask-filling model | T5-base (CPU) |
| Calibration | Enabled |

## 6. Deviations from Paper & Findings

### 6.1 Full Fine-tuning vs. LoRA

The paper states LoRA as its default PEFT method. We found that LoRA on GPT-2 base produced AUC ≈ 0.52 (random performance) across multiple runs. Investigation showed that with LoRA, the target model's loss on training texts (~3.61) was indistinguishable from the reference model's loss (~3.61), causing the calibration step to cancel out all signal.

Full fine-tuning produced a clear loss gap between the target and reference models for member texts, restoring the attack signal.

| Configuration | AUC | Notes |
|---|---|---|
| gpt2-xl, full fine-tune, AG News, 200 samples | 1.000 | Trivial — extreme memorization |
| gpt2 base, LoRA, Wikitext-103, 10k samples | 0.536 | Random — no signal |
| gpt2 base, LoRA, Wikitext-103, 50k samples | 0.518 | Random — data size not the cause |
| **gpt2 base, full fine-tune, Wikitext-103, 50k samples** | **0.977** | **Matches paper** |

### 6.2 T5 on CPU (Mac-specific)

On Apple MPS, T5-base generation produced empty outputs, breaking the perturbation step entirely. Forcing T5 to run on CPU resolved this. This fix is specific to Apple Silicon and would not be needed on NVIDIA hardware.

### 6.3 Training Data Size

The paper does not specify the exact number of training samples used. We found 10,000 samples insufficient and settled on 50,000, which produced results matching the paper.

## 7. How to Reproduce

The repository includes a single script that runs the entire pipeline end-to-end:

```bash
cd ~/SPV-MIA
bash _run_pipeline.sh
```

Expected runtime: ~10–12 hours on Apple Silicon 192GB.

After completion:
```bash
python3 save_results.py
```

Results are saved as a timestamped JSON file in `results/`.
